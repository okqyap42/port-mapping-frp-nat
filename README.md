## 一、“端口映射服务器”可能指两件完全不同的事

搜索这个词的人，八成想的是“把内网端口暴露到公网”。但在 Linux 系统里，portmap（现在叫 rpcbind）是一个具体服务，跑在 111 端口上，干的是另一件事。两者混在一起讲，配置方向就会跑偏。

**rpcbind：帮 RPC 程序找端口**

RPC 服务启动时会随机挑一个空闲端口，然后向 portmap 注册，告诉它“我是哪个程序号、在哪个端口监听”。portmap 维护一张映射表，字段包括程序号、版本号、协议、端口号和服务名。客户端要调用某个 RPC 服务，先向 portmap 查询实际端口，拿到端口后直接连过去，后续通信不再经过 portmap。

它只在第一次建立连接时起作用。连接建立、端口和应用绑定之后，portmap 就退场了。这个服务默认监听 TCP 和 UDP 的 111 端口，从 CentOS 6 / RHEL 6 起更名为 rpcbind，功能没变。历史上出过 CVE-1999-0632 这类远程漏洞，不用 NFS 的机器可以直接关掉：`systemctl stop rpcbind`、`systemctl disable rpcbind`。停之前要先停掉 NFS 等依赖服务。

**家用和云上的端口映射：把公网端口转到内网**

路由器里的“虚拟服务器”、云厂商控制台的“NAT 端口映射”、FRP 的 `remote_port`，说的都是这件事：外部访问某个公网 IP 的指定端口，流量被转到内网某台机器的某个端口。TP-Link 的虚拟服务器就是基于 NAT 实现，四个要素是外部端口、内部端口、内部 IP、协议类型。比如把公网 8080 映射到 192.168.1.100 的 80 端口，协议选 TCP，浏览器打开 `http://公网IP:8080` 就能看到内网的 Web 服务。

111 端口那个 rpcbind 不要暴露到公网；NAT 端口转发才是你要找的东西。

**路由器虚拟服务器**的配置路径以 TP-Link Archer AX6000 为例：浏览器进 `192.168.1.1` 或 `tplinkwifi.net`，高级设置 > NAT转发 > 虚拟服务器，填服务名称、外部端口、内部端口、内部 IP、协议（TCP/UDP/BOTH）。映射完打不开，按顺序查三件事：内网服务有没有起来、防火墙有没有放行、运营商有没有封这个端口。

**FRP** 是 Go 写的反向代理工具，跨 Windows、Linux、macOS，支持 TCP、UDP、HTTP、HTTPS 和 TLS。frps 部署在公网服务器，frpc 部署在内网设备，frpc 主动连 frps 建立隧道，外部访问 frps 的指定端口，流量经隧道转到内网服务。它解决的是“内网设备没有公网入口”这个问题，和路由器映射的区别在于：映射要求你做端口转发的那台设备本身有公网 IP，FRP 只要求你有一台能连出去的内网机器。

**NAT VPS** 是一台没有独立公网 IPv4 的虚拟服务器，多个用户共享一个公网 IP，商家把 IP 上的若干端口（比如 30000–30010）分给你。你在商家面板里配转发规则，或者在机器上用 iptables 做 DNAT，把进入这些端口的流量转到目标设备。它和独立 IP 云服务器的区别就在 IP 和端口：前者是共享 IP 加固定几个端口，后者是整个 IP 归你，端口随便开。

## 四、FRP 最小可用配置

新版 FRP 用 TOML 格式，旧版的 `.ini` 配置仍然能查到很多教程，但新版本以官方 releases 页面为准。下面的写法只说明配置结构，具体版本号不要照抄。

服务端 `frps.toml`：

toml
bindPort = 7000

auth.token = "换成一串足够长的随机字符"


客户端 `frpc.toml`：

toml
serverAddr = "公网服务器IP"
serverPort = 7000

auth.token = "与服务端完全一致"

[[proxies]]
name = "ssh"
type = "tcp"
localIP = "127.0.0.1"
localPort = 22
remotePort = 8001


启动后，访问公网 IP 的 8001 端口，流量会经隧道转到内网机器的 22 端口，命令是 `ssh -p 8001 user@公网IP`。第二台内网机器复制一份配置，把 `name` 改成不同的值、`remotePort` 改成 8002，就能用 `ssh -p 8002` 连第二台。

三件事不做，配置对了也连不上：

1. **token 必须一致**。这是防止别人蹭你中转的基本防护，token 泄露等于把隧道借给别人用。
2. **云服务器安全组要放行**。7000 是 frpc 连服务端的端口，8001、8002 是外部访问的端口，两个方向都要开。
3. **配 systemd 自启**。进程被误杀或服务器重启后不自动拉起，远程访问就断了。服务文件里写 `Restart=always`、`RestartSec=5`、`LimitNOFILE=65535`，然后 `systemctl daemon-reload`、`systemctl enable frpc`、`systemctl start frpc`。验证方式是 `pkill frpc`，等几秒看进程有没有自己回来。

安全上再做两步：内网 SSH 改成证书登录、关掉密码登录；远程端口只允许自己的 IP 访问，别对全网开放。

## 五、几个最容易踩的坑

**运营商封端口**。80、25、443 这类常用端口在不少地区被封，映射到这些端口会表现为“配置全对但外网打不开”。换成 8080、8443 这类高位端口通常能解决。

**光猫 + 路由器多层 NAT**。家里既用光猫拨号又接了路由器，端口映射要做在光猫上，或者在光猫里给路由器开 DMZ。只在路由器上配，外网流量到不了路由器这一层。

**动态 IP 会变**。家宽的公网 IP 不是固定的，重启光猫就换一个。要给外网一个稳定入口，得配 DDNS，把域名绑到当前 IP 上。

**rpcbind 的 111 端口别对外开放**。这个端口和端口映射无关，暴露在公网只会增加被扫描的风险。

**远程桌面不要直接映射 3389**。改成五位数的高位端口，再配合只允许特定 IP 访问，能挡掉大部分自动化扫描。

**游戏云的 NAT 端口数量有限**。15 个端口对开一个私服够用，要映射的服务多了就会不够。

## 七、常见问题

**端口映射和端口转发是一回事吗？**
在 NAT 语境下基本是同一件事的两种叫法，都是把公网端口的流量转到内网地址。路由器叫“虚拟服务器”，云厂商叫“NAT 端口映射”，FRP 叫 `remote_port`。

**没有公网 IP 能不能做端口映射？**
能，但需要一台有公网 IP 的中间机器。两条路：自己买云服务器跑 FRP，或者买 NAT VPS 用商家分配的共享 IP 和端口。

**NAT VPS 的端口为什么只有几个？**
因为公网 IP 是多个用户共享的，端口是稀缺资源。常见配置是 10 到 15 个，够映射 NAS、远程桌面、一两个网站。要全端口就选独立 IP 机型。

**用 FRP 需要备案吗？**
备案针对的是域名和网站内容。只用 IP 加高位端口访问 SSH、远程桌面这类服务，不涉及备案；一旦用域名在国内服务器上对外提供网站服务，就需要走备案流程。

**配置全对，为什么还是连不上？**
按这个顺序查：内网服务本身能不能在本机访问、云服务器安全组有没有放行、本机防火墙有没有放行、运营商有没有封端口、frpc 进程有没有在跑、token 是否一致。这六项里总有一项是漏的。
